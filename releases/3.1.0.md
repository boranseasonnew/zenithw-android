# ZenithW Android 3.1.0

## What's Changed

This update expands ZenithW's on-device download and media-management workflows while keeping the home screen focused on your link. There are no accounts, ads, analytics SDKs or paid cloud services.

- Share one or several links from other apps, open configuration immediately, and load metadata asynchronously. Repeated share deliveries are filtered. Direct downloading from shares is a separate, opt-in preference.
- Manage a persistent queue with priorities, reordering, move-to-top controls and a configurable limit of 1–5 concurrent downloads (default: 2). Wi-Fi, unmetered, charging and scheduled-work conditions are supported. Temporary network failures use bounded retries.
- Search and filter your library, switch between list and grid views, mark favorites, organize collections and perform bulk sharing/export. Removing an entry and permanently deleting its files are separate choices.
- Use local SAF files for conversion, audio extraction, lossless MP4/MKV remuxing, muting, stream-copy or re-encoded trimming, GIF/animated WebP export and supported subtitle operations. Tools check the bundled FFmpeg capabilities before exposing encoder-dependent operations. Originals are preserved.
- Select actual source chapters or multiple clip ranges. Compatible clips can be merged; separate files are retained if safe merging is unavailable.
- Save source-specific format profiles and use optional rule-based Smart Mode suggestions with manual overrides. Naming templates have a live preview and path validation.
- Review duplicate versions before downloading another copy. Different formats, qualities and clips are treated separately.
- Import bounded TXT link lists with validation, duplicate counts and a preview. The existing 50-row batch limit remains.
- Export/import versioned settings backups. Cookies, passwords, encryption keys, proxy credentials and device folder grants are excluded. Restoring keeps the current history-retention preference, and imported naming templates cannot read private HTTP headers. Optional favorite/collection metadata is applied only to existing matching records.
- Review inactive private download and conversion leftovers with Storage Guard before deleting them. Active work and original files are protected.
- Improve recovery explanations and preserve privacy-safe diagnostic logs. Fix legacy history records with missing/non-finite progress values.
- Add new interface strings in Turkish, English, German, French and Russian.

## Validation

The signed GitHub Actions release passed 61 Android 13 tests, 23 Android 7 compatibility checks, 32 Python tests, the Kotlin policy checks and Android lint. A separate physical Android 13 phone passed 28 tests, including real native media conversion, trimming, animation, subtitle operations and cancellation. Existing release signing and stable package identity were preserved.

## Compatibility and limitations

- Android 7.0+ remains the minimum. Stable, Preview and F-Droid identities remain separate.
- Pause applies to queued items. Stopping an active download uses cancellation and an explicit restart; this is not presented as guaranteed partial-download resume.
- Stream-copy cuts follow keyframes. Accurate cuts require re-encoding and take longer.
- GIF/WebP processing is bounded to short clips and limited dimensions/frame rates. Subtitle burning and other encoder-dependent operations appear only when the bundled build supports them.
- A restored backup does not transfer Android file permissions, recreate missing media or automatically restart another device's queue. Sensitive session export is not offered.
- Source restrictions, expired sessions, HTTP 403 and anti-bot challenges cannot always be resolved.
- **Full native 16 KB memory-page compatibility is unresolved.** The pinned browser executable still has 4 KB ELF alignment. APK ZIP alignment does not fix that limitation.

See the repository's [engineering report](https://github.com/boranseasonnew/zenithw-android/blob/main/docs/android-3.1.0-report.md) for actual validation results and remaining verification limits. A successful build is not a claim that every device, document provider or source has been verified.
